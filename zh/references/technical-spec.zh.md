# 项目技术说明：数据、模型、目标与评估

初始化时建立说明，训练前检查本次变化，训练后记录实际采用的版本。目标是让下一次探索能回答：使用什么样本、做过什么处理、模型算什么、优化什么、结果如何比较。源码快照和路径索引提供依据，可读说明解释其含义。

## 必须覆盖的八类内容

各类都要检查并填入已经查明的事实。不适用的项目简短说明；查不到的关键项注明缺少的具体来源。不要让用户填写能从代码、配置或产物中提取的内容。

| 类别 | 要记录的内容与含义 | 默认保存位置 |
|---|---|---|
| 任务与样本 | 任务目标；一个样本是什么；样本/实体/帧身份；输入、条件、目标、输出的字段、形状、单位和 mask；标签来源 | `specs/data.md` |
| 数据来源与版本 | 原始来源、生成方法、版本/清单/哈希；原始→清洗→特征→缓存的数据血缘；各阶段路径、数量和生成代码；训练实际使用的身份 | `specs/data.md`；MLflow 数据标识与清单 artifact |
| 清洗与预处理 | 有序处理步骤、筛选/去重/缺失值规则、阈值及边界、作用单位和集合、规则交集/并集；标准化拟合范围、截断/填充/特征计算；处理前后数量、排除原因与清单 | `specs/data.md`；配置与统计 artifact |
| 划分与采样 | train/val/test 和 ID/OOD 的具体定义、划分单位/seed/清单；跨集合共享什么；增强、重采样、混合比例、帧/序列选择与有效样本量 | `specs/data.md`；run 配置 |
| 架构与初始化 | 从输入到输出的模块流、维度/层数/连接方式；总参数与可训练参数；预训练来源、冻结/训练范围、条件与梯度流；相对基线的改动 | `specs/model.md`；模型配置和源码 artifact |
| 损失与优化目标 | 总目标、分组和所有叶子项的公式及实现位置；符号、单位、目标来源、mask、归一化/分母/reduction；固定/动态权重和层级关系、梯度作用对象 | `specs/objective.md`；指标字典、权重配置/曲线 |
| 训练协议 | 实际入口、命令、解析后的配置；优化器、调度、有效 batch、非均匀多卡/累积、更新次数、精度、裁剪、seed；主机 RAM/缓存预算与预加载策略；训练阶段、恢复来源及恢复的状态 | `specs/training-eval.md`；params/config/code artifacts |
| 评估与模型选择 | 全量验证集/固定 quick 子集身份与缓存范围、推理/采样/rollout/后处理；各指标公式和聚合；quick/full 频率、best/final 选择与并列规则；比较所用 checkpoint 和共同协议 | `specs/training-eval.md`；指标与评估 artifact |

已有文档覆盖这些内容时直接复用并链接；按项目规模可以合并文件。技术说明集中定义含义，主题笔记记录本次改动、主要结果和发现，不为每个 run 复制整套说明。

## 从实际执行链读懂项目

从近期真实运行的启动配置或 manifest 开始，追踪到入口、数据加载与变换、batch/collate、模型 forward、loss、backward、验证和 checkpoint 选择。尚无运行时从已确定的计划入口开始，并注明是计划。README 用于定位，运行配置与对应源码用于解释具体实验。源码包包含历史或嵌套副本时，确定入口实际导入的精确成员路径，不只按文件名选择。

选取现有小样本或样本 schema，说明关键张量怎样改变形状、单位、mask 和含义。优先静态追踪；必要时使用已有小型检查，不为初始化启动完整训练。冻结模型、离线缓存、在线条件和多阶段训练要画清依赖关系：记录缓存生产者与 checkpoint，确认哪些分支参与当前执行。

每条活跃训练路线至少说明其输入、模型、目标、评估及相对基线的变化。共用部分引用项目说明，仅展开差异。区分当前默认、实际 run 配置、部署源码快照和计划变更；同名文件在不同 worktree 中的实现分别归属，最新清洗规则也不自动成为旧 run 的数据版本。

损失必须同时有**可读公式和实现定位**，不能只填函数路径。总项、组项、叶子项覆盖到实际参与目标的层级；代码未发布的叶子指标仍须说明定义，并将“已计算”和“已记录”分别列明。非加性目标按实际公式描述；含子项权重的 `raw` 变量要解释，不能仅凭名称归类。

例如平方坐标误差除以 N 还是 3N、先逐样本开方再平均还是整体开方，会改变比较含义。公式旁写清这些选择，以及训练目标与验证指标的关系。公式或处理规则复杂时，展开影响当前探索的细节，其余链接到已完整的专门文档。

## 版本与维护

说明的每个关键结论关联文件/符号/配置键及代码或数据版本；当前未提交文件可附内容哈希，历史实验优先使用自身快照。参数数量等实测量注明对应模型配置与获取方法，无法获取时列出具体缺项。

训练前在主题笔记记录基线、数据/模型/目标/协议四方面的变化，以及预期观察。实际启动时给 run 保存技术说明与解析配置的快照或不可变版本引用，MLflow artifact 可用 `specs/`。项目文档后续更新不改变历史 run 的说明。

训练后补充实际偏离计划的配置、数据与评估变化，并连接主结果。新的收益判断仍按用户交流后写入的流程处理。变更触及数据、模型、目标或协议时，同时更新对应说明、指标定义和相关路径图节点；只更新受影响部分。

## 与用户交流

先呈现已提取的项目理解，再集中询问真正影响探索的决策，例如要比较哪个基线、采用哪个数据版本、需要哪些分项曲线。无法从现有证据取得的事实单列为待补来源。用户决定研究方向和收益判断，AI负责把实现与证据解释清楚。
