# 结果、发现与后续探索

## 先整理事实，再交流含义

训练后读取指定 runs 的真实记录和已有主题笔记，整理运行状态、训练进度、主要指标、checkpoint 和基线差异。只获取当前问题需要的历史与产物。数值对比可以自动计算，研究收益与决策在交流中确定。

围绕以下内容讨论，已有答案直接复用：主要结果是什么；用户认为它说明什么；哪些发现值得保留；下一步已决定做什么。展示必要数字和图表，便于讨论。没有要求判定成功或失败时，保留具体结果即可。

“每个指标各自的历史最好值”和“同一个 checkpoint 上的一组指标”分别说明；摘要中的比较对象、评估集和 step 应可追溯。

## Markdown 作为分析主稿

一个研究主题对应一份可关联多个 runs 的笔记，默认使用 `notes/<study>.md`。常用内容：问题与主要改动、关联 runs、主要结果、主要发现、后续决定、重要产物。只保留实际有内容的栏目。

主要结果保留支撑理解的关键数字；loss 历史、完整参数和全部路径放在 MLflow 或路径图中。每项重要发现附相关 run、图表或产物链接。将观察事实与已经讨论的解释写清楚，不自动添加置信度等级、实验成败标签或固定免责声明。

用户说“记录下来”时，写入最近明确指向的内容。只是询问“你怎么看”时，继续分析，不把候选解释写为已确定发现。用户明确要求记录一个假设时，按“假设”保存即可。

多次实验后维护“当前认识”，并保留简短的按日期更新记录。结论改变时，更新当前认识，说明对应的新证据。用用户当前时区的日期和明确时区记录时间。

## 同步到 MLflow

本地主题 Markdown 是分析主稿，MLflow 保存与本次发布对应的摘要和附件。用 `MlflowClient` 明确指定已有 run ID，避免通过 `start_run` 补写分析改变 run 状态或结束时间。

1. 保存本地 Markdown，选取本次已确定的摘要。
2. 使用 `mlflow.note.content` 更新描述中的日志管理段；保留既有的其他描述内容。
3. 上传完整 Markdown 为 `analysis/<study>/<revision>.md`，revision 使用时间加内容哈希等稳定方式；重复发布同一版本复用标识。
4. 在自定义 tags 中记录分析版本和 artifact 路径；在主题笔记与路径图里保持 run 关联。

支撑发现的图、比较表和路径图快照随同一不可变分析版本发布，用清单或链接定位到该版本的实际附件。只给笔记版本号、却让图表被后续覆盖，不能保留当时证据。当前导航入口与历史发布文件分开；增加 run 或修改发现时保留旧版本，仅当笔记及支持证据都未变化时复用原版本。

从发布包的实际位置检查链接，包括复制进去的 HTML 和支持 Markdown 内部链接，不能只检查主笔记。保留所需目录结构，或重映射链接并纳入依赖文件；指向外部训练资产的链接应明确。

可使用 `<!-- experiment-journal:start -->` 和 `<!-- experiment-journal:end -->` 标记所管理的描述段。已有无标记描述时追加该段，以后只更新该段。

多 run 分析为各相关 run 写入适用摘要和同一版本附件。新计算的评估量按其定义另记 metrics；分析正文不放 params。若两处仅一处保存成功，说明已保存位置和待同步项，下次继续该版本。

## 路径图与后续

更新运行状态、代码快照和产物位置等客观信息；只把用户已确定的发现摘要和决定加入图中。把后续想法记录为建议或计划，与已执行分支区分。查看下一轮实验前，先读当前认识和相关路径图节点。
