# exp/experiment-journal

除整理记录外，也实现和执行用户要求的实验变体。围绕四件事组织工作：**和人明确什么、记录什么、内容是什么意思、用什么形式保存与展示**。MLflow 保存数值、配置、代码与产物；Markdown 保存主要结果、发现和后续决定；实验路径图连接研究路线、代码分支、runs 与实际文件位置。同时维护优先阅读的重要信息概览：简短展示关键配置、loss、结果和版本间改动，完整溯源另保留。

## 中英文维护

`zh/SKILL.zh.md` 和 `zh/references/*.zh.md` 是用户编辑的中文源稿；根目录 `SKILL.md` 和 `references/*.md` 是供 AI 使用的英文对应稿。

版本更新由用户手动安排。日常使用直接读取英文版，不执行中英文变更检查，也不自动翻译或同步。用户要求“同步英文版”时，再按中文源稿更新对应英文；用户要求修改 skill 时，按其指定范围维护两个版本。

保持中英文技术标识、字段、默认值和文件链接对应；中文内部链接指向中文参考文档，英文链接指向英文文档。用户可直接说“同步英文版”。默认用中文与用户交流，记录语言沿用项目习惯。

## 工作方式

先读取项目当前需求、主题实验的具体需求、已有约定、相关配置和最近的实验记录。整理已知信息，只讨论会影响本次记录的缺项。给出短小的具体选项或建议，例如“沿用原始验证 loss，新增 ID/OOD 成对图”。首次配置确定通用默认，以后主要讨论变化。

AI 可以提取事实、核对数值和参与分析。实验是否成功、收益在哪里以及后续决定，由用户在交流中确定。讨论中的候选解释保持在交流中；收到“记录下来”等明确指令后，直接写入相应发现，不逐项重复确认。训练状态和研究结论分别记录。

按当前任务读取参考文档：

| 场景 | 读取内容 | 产物 |
|---|---|---|
| 已有项目首次纳入、历史实验整理、初始化 | [项目初始化](references/initialization.zh.md)，按需要读取下面的专题 | 有实际内容的需求记录、记录纲要、证据清单、项目约定、初始路径图与已有发现 |
| 梳理或修改数据、架构、目标及协议 | [项目技术说明](references/technical-spec.zh.md) | 有版本依据、可读的数据/模型/目标/训练评估说明 |
| 实现、执行或比较模型/代码变体，并行实验开发 | [实验执行与隔离](references/experiment-execution.zh.md)，再按需要读下面的技术规范 | 隔离变体、已检查的启动路径、真实 runs 及可溯源对比 |
| 训练前准备、首次接入 | [训练前与元数据](references/before-training.zh.md)，涉及指标时读 [指标与对比](references/metrics-and-comparison.zh.md) | 本次记录方案、配置、所需接入 |
| 查看曲线、跨 run 或 ID/OOD 对比 | [指标与对比](references/metrics-and-comparison.zh.md) | 图表或主要结果对照 |
| 训练后整理、补写发现 | [结果与发现](references/results-and-findings.zh.md) | Markdown、MLflow 摘要与附件 |
| 查看或更新研究路线、分支、路径 | [实验路径图](references/experiment-map.zh.md) | 结构化索引、Excalidraw 图、Markdown/Mermaid 总览 |

初始化和训练前还需读取[项目技术说明](references/technical-spec.zh.md)和[指标含义与比较](references/metrics-and-comparison.zh.md)，覆盖八类基础内容，追踪实际执行链，解释公式与数据流。路径清单或格式正确的图本身不能作为理解项目的完成标准。

执行按研究问题/预算 → 隔离变体 → 实现与技术说明 → 小测试 → 授权范围内运行 → 实测比较 → 讨论后写发现推进。独立开发的代码变体默认分别使用 branch/worktree；固定代码的 seeds/重复运行分别有 run。各 worktree 共用唯一日志根目录，准备工作区前读取执行文档。

GPU 训练必须在训练前和训练中采样利用率，原则上每卡稳态训练平均利用率应超过 90%。按执行文档落实采样、瓶颈调整和证据记录。

预加载前明确 run 的主机 RAM 与缓存预算，优先缓解训练 I/O，再安排验证子集常驻或预加载。新实验通常使用固定 10–20% 子集做常规验证，每隔计划总 epoch 数的 2.5% 及 final 做全量验证（200 epoch 时每 5 epoch 一次）；按执行与指标文档区分两种结果口径。

训练程序负责持续记录，skill 不需要在每个 step 调用。准备记录和写入发现本身不启动完整训练；训练执行沿用用户当前任务的授权。

## 主动维护

在已有 `tracking.json`、`experiment-map.json` 或项目日志约定的项目中，需求被明确调整、实验相关代码或分支变更、run 启动/恢复/结束、产物位置变化以及发现被明确记录，都触发本 skill 的增量维护。目标或记录需求变化时更新需求文档；数据、模型、目标或协议变化时更新对应技术说明；图中事实变化时定位受影响节点、补充证据并重新生成两种图。无需等用户另说“维护记录”；没有变化时保持文件不动。

初始化时把 `assets/project-hook.zh.md` 或英文对应稿中的约定合并进项目的 `AGENTS.md`，沿用既有内容与语言，让后续会话也能主动选择本 skill。这个触发机制发生在 AI 执行相关任务或检查到变化时；后台训练需要即时刷新时，在已有训练回调里接入事件更新，具体方式见路径图文档。

## 项目级约定

优先沿用已有目录与命名。新项目默认使用 `experiments/`：

```text
experiments/
  requirements.md        # 项目当前目标、记录需求、优先事项和已确定约束
  specs/                 # 数据、模型、目标、训练评估说明；可复用已有文档
  tracking.json          # 地址、指标字典、记录频率、对比预设
  initialization.md      # 记录纲要、历史整理范围和仍需明确的事项
  evidence.json          # 已有数据与证据的索引
  experiment-map.json    # 实验与分支、代码版本、runs、路径的结构化关系
  experiment-map.overview.excalidraw # 重要配置、loss、结果和版本改动概览
  experiment-map.overview.md # 概览背景、选入范围和详情入口
  experiment-map.excalidraw # 主路径图，可编辑布局与添加批注
  experiment-map.md      # 同源生成的 Mermaid 总览和详细表格
  notes/<study>.md       # 主题实验的具体需求与计划、主要结果和发现
```

`assets/tracking.example.json` 提供可裁剪的结构示例；示例值用于说明结构，首次接入时用实际配置替换。`assets/experiment-map.empty.json` 是路径图的空索引。`assets/note-template.zh.md` 与 `assets/note-template.en.md` 提供记录模板。只创建当前任务需要的文件。

初始化必须创建或更新有实际内容的需求记录，参考 `assets/requirements-template.zh.md` 及其英文对应稿。项目已有适用的需求文档时直接更新并链接。只初始化单个实验时，把当前需求与计划写入对应主题笔记，并关联适用的项目需求，不为每个 run 重复创建项目文档。

把已确定的 loss 含义、映射和展示方式写入项目配置。每次 run 保存当时的配置快照，后续修改项目默认不改变历史记录。

## 写作与交付

以用途、默认做法和具体结果为主。一个段落说明一个要点，字段和比较用表格；有助于理解时再给示例。发现应包含必要的关键数字、比较对象及证据链接。限制说明只写确实影响本次理解的具体问题，不附加固定的置信度评分或保守结语。尚未讨论的栏目可省略。

结束时简短说明保存位置、相关 runs、路径图更新和具体待补项。新发现的项目特例先保存在项目约定中，反复出现的通用做法再纳入 skill。
